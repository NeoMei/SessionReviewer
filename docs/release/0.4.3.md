# 0.4.3

User acceptance is complete. This document describes the 0.4.3 release scope;
publication is established by the successful tag workflow and verified Release assets.

SessionReviewer restores the five-page project workflow: evolution, problems,
decisions, Sessions, and usage. The interface uses compact cards, grouped actions,
clear status labels, and layouts that adapt to the Obsidian pane width.

- Create and edit problem nodes; confirm, split, merge, move, and reorder explicit
  recommendations while preserving accepted human changes.
- Create and edit decisions; explicitly extract candidates, inspect supporting
  evidence, confirm, ignore, reject, or restore them.
- Read authenticated Session questions and Agent answers with pagination, exact
  historical references, retained-source fallback, and private fact search.
- Query ModelPriceWatch, confirm the actual billing route, and keep immutable
  price snapshots. Unknown prices remain unknown.
- Scan, read, and organize by deterministic rules without invoking an Agent.
  Candidate extraction invokes an Agent only when explicitly requested.
- Retain bounded text from Codex image attachments that previously caused the
  entire user message to be skipped. Historical reading rules remain stable.
- Check release provenance, exact asset names, downloaded checksums, and mainline
  identity before promoting a GitHub draft. Restore the 0.3.0 and 0.3.1 Obsidian
  compatibility entries.

## Coverage and acceptance limits

The actual Codex Session experiment recovered 14 user turns instead of 12.
The frozen source still contains 106 oversized records and 463 unsupported
execution records. These counts do not represent missing human-message counts.
Output bodies without trustworthy exit metadata cannot establish successful
verification or produce a verified milestone. Partial coverage remains visible.

The OpenCode SQLite adapter is opt-in. Fixture checks and a read-only live-store
discovery probe do not establish acceptance of historical OpenCode content.
Claude historical-client acceptance is not claimed. Exact Codex resume and the
five-page visual result were confirmed by the user during final acceptance. New platform expansion and legacy-project migration are outside this
repair; existing compatibility checks remain.

Remote platform CI, signed provenance, public downloads, BRAT upgrade,
and daily-Vault installation are separate publication/installation gates. Local
candidate checks do not certify those later outcomes.

## Upgrade

Back up existing review/history documents and machine-local accepted state.
Install the CLI and the three matching plugin assets (`main.js`, `manifest.json`,
`styles.css`) together. Rescan explicitly to use the new conversation rule;
historical snapshots retain their original interpretation. Do not delete human
documents to force initialization or migration.
